Code + collaboration

GitHub

Google Docs for code: a free place to store projects, track every change, and work on them with other people. It can also turn a project into a live website.

By GitHub (owned by Microsoft)

What it is

GitHub is a website built on Git, a tool that saves every version of your files. A project lives in a repository (repo), which is just a folder with a full history. You can see who changed what and go back to any earlier version. This club site is a GitHub repo, and its website is hosted by GitHub too.

Why people use it

  • Nearly every software team and AI project, including most open models, keeps its work on GitHub.
  • Teams review each other's work before it goes live, which prevents costly mistakes.
  • GitHub Pages hosts a website from a repo for free, with no server to manage.
  • A public GitHub profile works as a portfolio that employers and investors can check.

How to get started

  1. Create a free account at github.com.
  2. Open this club's repo (TheJ1u/ai-for-life) and click around. Every file is readable.
  3. Click Fork to make your own copy. You cannot break the original.
  4. Open a file, click the pencil icon, make a change, and Commit it. A commit is a saved version with a note.
  5. Click Contribute, then Open pull request to suggest your change to the club repo. The owner reviews it and clicks Merge if it looks good.

Try this

git clone https://github.com/TheJ1u/ai-for-life.git
cd ai-for-life
git add .
git commit -m "Describe what you changed"
git push

These are the commands for working on your own computer. To start, skip them: you can do everything above in the browser. Learn the commands once you have made a few changes on the website.

Why it matters for business and IS

Information Systems angle: GitHub is how organizations control change. Every edit is recorded, reviewed and reversible, which supports audits, teamwork and quality. For a startup it also means a website or product can launch with almost no hosting cost.

Business use case

Scenario: A student team or startup needs a simple landing page and wants everyone to be able to edit it without breaking the live site.

How it works: Put the site in a repo, publish it with GitHub Pages, and have teammates propose edits as pull requests. The owner reviews each one before it goes live.

Measure success by: Hosting cost (zero), time to publish a change, and fewer mistakes reaching the live site.

Watch out for: Never commit passwords, API keys or private customer data. A public repo is readable by anyone.

Quick facts

  • Free for individuals, including public repos and GitHub Pages. Paid plans exist for teams and extra features.
  • Key words: repo, commit, branch, fork, pull request, merge, GitHub Pages.
  • Never put passwords or API keys in a public repo. Anyone can read them.

What to learn next

Make one small edit to this repo and open a pull request. Then learn git add, commit and push on your computer, and try the 'Build your own model' guide, which also uses GitHub.
